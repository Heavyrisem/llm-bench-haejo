# 롱컨텍스트 벤치마크 요청 (Qwen3.8-27B · 10k / 50k / 100k / 200k)

같은 입력으로 여러 환경의 프리필·디코드·TTFT를 비교하려고 합니다.
이 폴더의 `ctx_*.md` 4개를 **그대로** 프롬프트로 넣고 측정해 주세요.

측정 도구는 정해두지 않습니다. 각자 환경에서 쓰던 방법(백엔드 내장 벤치, 서버 로그, 직접 만든 클라이언트, GUI의 통계 표시 등)을 쓰되, 아래 "측정 조건"만 지켜주시면 됩니다.

## 입력 파일

| 파일 | 토큰 수 (Qwen3 토크나이저, 파일 내용만) |
|---|---:|
| `ctx_10k.md`  | 9,999   |
| `ctx_50k.md`  | 49,999  |
| `ctx_100k.md` | 99,999  |
| `ctx_200k.md` | 199,998 |

- 챗 템플릿을 거치면 시스템 프롬프트와 역할 토큰만큼 수십 토큰이 더 붙습니다. 정상입니다.
- 내용은 퍼블릭 도메인 영어 소설 4권을 이어붙인 자연어 텍스트이고, 파일 끝에 태스크가 있습니다.
- 태스크는 "위 텍스트를 장별로 상세히 요약하라, 최소 2000단어"입니다. 디코드가 max_tokens 전에 끝나지 않게 길이 하한을 걸어둔 것입니다.
- **파일을 수정하지 마세요.** 토큰 수가 달라지면 비교가 깨집니다. 캐시 무효화용 논스는 파일이 아니라 요청 시점에 앞에 붙입니다 (아래 참고).

## 측정 항목 정의

파일당 아래 3개를 받습니다. 정의를 만족하면 어떤 도구로 측정해도 됩니다.

| 항목 | 정의 | 단위 |
|---|---|---|
| **TTFT** | 요청이 서버에 도착한 시점 → 첫 생성 토큰이 나온 시점 | 초 |
| **prefill** | 프롬프트 토큰 수 ÷ 프롬프트 처리 시간 | tok/s |
| **decode** | 첫 토큰 이후 생성된 토큰 수 ÷ 그 토큰들을 생성하는 데 걸린 시간 | tok/s |

- 프롬프트 토큰 수는 **실행한 서버가 센 값**을 씁니다 (응답의 `usage.prompt_tokens`, 서버 로그, 벤치 도구 출력 등). 위 표의 값과 몇십 토큰 차이는 무시해도 됩니다.
- 서버가 프롬프트 처리 시간을 직접 알려주면 (예: llama.cpp의 `prompt_ms`) 그 값이 클라이언트에서 잰 TTFT보다 정확하니 그걸 쓰세요. 없으면 클라이언트 TTFT로 계산합니다. 어느 쪽인지 적어주세요.
- 생성 토큰 수도 서버가 센 값(`usage.completion_tokens` 등)을 우선합니다. 없으면 스트리밍 청크 수로 근사해도 되고, 그 경우 그렇게 표기해 주세요.

## 측정 조건

1. **콜드 프리필**. 같은 프롬프트를 두 번 보내면 두 번째는 프리픽스 캐시가 먹어서 TTFT가 거의 0이 됩니다. 아래 둘 중 하나로 막아주세요.
   - 서버의 프롬프트/프리픽스 캐시를 끄고 실행
   - 또는 매 요청마다 프롬프트 **맨 앞**에 매번 다른 한 줄을 붙이기 (예: `run 3 / 14:02:11`). 앞부분이 다르면 캐시 전체가 무효화됩니다.
   - 캐시가 끼었는지는 TTFT로 바로 티가 납니다. 100k 프롬프트에서 TTFT가 1초 미만이면 캐시입니다.
2. **웜업 1회**. 모델 로딩, 그래프 캡처, JIT 컴파일 등이 첫 측정에 섞이지 않게 짧은 요청을 한 번 보낸 뒤 측정합니다. 모델 로딩 시간은 포함하지 않습니다.
3. **생성 최대 2048 토큰** (max_tokens = 2048). 태스크가 2000단어 요약이라 대부분 끝까지 채웁니다. 실제 생성 토큰 수를 같이 적어주세요.
4. **동시 요청 1개**. 배치 효과 없이 단일 요청 기준입니다. 다른 작업이 GPU를 쓰고 있지 않은 상태에서 돌려주세요.
5. **사이즈당 1회**만 측정합니다. 웜업 후 각 파일을 한 번씩 보내면 됩니다.
6. **thinking 끄기**를 기본으로 합니다. 끌 수 없는 설정이면 thinking 토큰도 생성 토큰에 포함해 계산하고 그 사실을 적어주세요.
7. **샘플링은 자유**입니다. 속도에 영향이 거의 없습니다. 다만 greedy가 아닌 설정을 썼다면 적어주세요.
8. **타깃 모델은 Qwen3.8-27B 고정**입니다. 양자화 형식은 각자 환경에 맞는 것으로 쓰시고 환경 표에 적어주세요.
   **드래프트 모델(스펙 디코딩)은 자율 선택**입니다. 안 써도 되고, 썼으면 종류와 드래프트 모델을 환경 표에 적어주세요.

## 회신 양식

결과는 아래 두 표로 보내주세요. 결과 표는 한 줄이 컨텍스트 하나이고, 환경 표는 항목/값 두 칸입니다.
특이사항이 있으면 표 아래에 50~100자 내외로 한 줄만 적어주세요. 없으면 생략합니다.

**결과**

```
┌──────┬───────────────┬──────────┬─────────────────┬────────────────┬────────────┐
│ ctx  │ prompt_tokens │ TTFT (s) │ prefill (tok/s) │ decode (tok/s) │ gen tokens │
├──────┼───────────────┼──────────┼─────────────────┼────────────────┼────────────┤
│ 10k  │               │          │                 │                │            │
│ 50k  │               │          │                 │                │            │
│ 100k │               │          │                 │                │            │
│ 200k │               │          │                 │                │            │
└──────┴───────────────┴──────────┴─────────────────┴────────────────┴────────────┘
```

**환경**

| 항목 | 값 |
|---|---|
| 환경 | <GPU / VRAM 또는 CPU / 메모리> |
| 백엔드 | <백엔드 + 버전> |
| 모델 | Qwen3.8-27B (고정) <모델 파일 + 양자화> |
| KV 캐시 | <타입, 양자화 여부> |
| 측정 방법 | <예: llama-server timings / vLLM 벤치 / 직접 만든 스트리밍 클라이언트 / LM Studio 통계> |
| 프리필 시간 출처 | <서버 보고값 / 클라이언트 TTFT> |
| 스펙 디코딩 | 없음 / <종류 + 드래프트 모델> (자율 선택) |

**특이사항:** <50~100자. 예: "200k는 컨텍스트 한계로 미측정", "100k부터 CPU 오프로드 발생", "thinking 끌 수 없어 포함 계산">

특이사항에 적을 만한 것:
- 일부 사이즈를 측정 못 한 이유
- 전력 제한, 클럭 오프셋, KV 캐시 양자화, CPU 오프로드, 멀티 GPU 등 기본값이 아닌 설정
- thinking을 끄지 못했거나, 생성이 2048 전에 끝난 경우
- 200k에서 요약 품질이 이상했던 경우

## 백엔드별 참고 (강제 아님)

- **llama.cpp / llama-server**: 응답 JSON의 `timings` 필드에 `prompt_n`, `prompt_ms`, `predicted_n`, `predicted_ms`가 있습니다. 이걸 그대로 쓰면 됩니다. 프롬프트 캐시는 요청에 `cache_prompt: false`로 끌 수 있습니다.
- **vLLM / SGLang**: 서버 로그의 per-request 지표나 각자 벤치 스크립트(`vllm bench serve` 등)를 써도 됩니다. 프리픽스 캐시 옵션을 끄거나 논스를 붙여주세요.
- **Ollama**: `--verbose`로 CLI를 쓰거나 API 응답의 `prompt_eval_count`, `prompt_eval_duration`, `eval_count`, `eval_duration`을 쓰면 됩니다.
- **LM Studio, Jan 등 GUI**: 응답 아래 표시되는 통계(tok/s, time to first token)를 그대로 옮겨 적어주세요.
- **MLX, TensorRT-LLM, 기타**: 각자 벤치 도구의 prompt/generation 지표를 쓰되 위 정의와 어떻게 대응되는지 한 줄 적어주세요.
- 내장 통계가 없는 서버는 OpenAI 호환 API로 스트리밍 요청을 보내 클라이언트에서 첫 청크 시각과 마지막 청크 시각을 재면 됩니다. 언어와 도구는 자유입니다.

## 문제가 생기면

- 컨텍스트 길이 초과 오류: 서버 최대 컨텍스트를 200k 이상으로 띄워야 합니다. 안 되면 되는 사이즈까지만 보내주세요.
- 200k에서 프리필에 몇 분 걸리는 것은 정상입니다. 클라이언트 타임아웃을 넉넉히 잡아주세요.
- 200k 요약이 엉뚱하면 (다른 소설 얘기, 같은 문장 반복) rope scaling이나 컨텍스트 설정 문제일 수 있습니다. 그 경우 속도 수치와 함께 알려주세요.
